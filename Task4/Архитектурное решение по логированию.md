# Мотивация

Сейчас основная боль — поиск причин проблем происходит вслепую и по словам клиентов, а разбор занимает часы и дни.

Внедрение централизованного логирования даст:

1. Сокращение времени расследования (MTTR)

    * Поддержка и разработчики смогут за минуты найти, что случилось с конкретным заказом или API-вызовом.
    * Появится возможность быстро отследить аномалии и восстановить последовательность событий без звонков клиентам.

2. Контроль качества интеграций

    * Партнёры B2B смогут получать чёткие ответы, что именно пошло не так и на каком этапе.

3. Снижение нагрузки на поддержку

    * 80% инцидентов можно будет решать сразу на 1-й линии, без привлечения разработчиков.

4. Раннее обнаружение проблем

    * Автоматические алерты по логам (ошибки, неожиданные паттерны, рост отказов) позволят реагировать до того, как клиенты заметят сбой.

---

### Метрики, на которые влияет логирование

Технические:

1. Среднее время расследования инцидента (MTTR).
2. Количество «потерянных» заказов, не найденных по логам.
3. Количество ошибок 5xx по сервисам.
4. Количество повторных сообщений в RabbitMQ (признак нестабильности).
5. Время поиска по логам (SLO поиска ≤ 2 сек для 95-го перцентиля).

Бизнес:

1. Количество обращений в поддержку, требующих эскалации на разработку.
2. Количество жалоб «не получили заказ».
3. SLA по времени ответа клиенту по проблеме.
4. Доля успешных заказов без ручных проверок.

# Системы, которые логируем в первую очередь

Так как сразу внедрить логирование и трейсинг во всём стеке невозможно, нужно определить приоритеты.

| Система            | Почему в приоритете                    | Логирование   | Трейсинг      |
| ------------------ | -------------------------------------- | ------------- | ------------- |
| Shop API       | Точка входа заказов и B2B API          | 1-й приоритет | 1-й приоритет |
| CRM API        | Статусы заказов и ручное подтверждение | 1-й приоритет | 2-й приоритет |
| MES API        | Производство, статус готовности заказа | 2-й приоритет | 1-й приоритет |
| RabbitMQ       | Потери сообщений, DLQ, ретраи          | 1-й приоритет | 1-й приоритет |
| Pricing Worker | Самая долгая и тяжёлая операция        | 2-й приоритет | 2-й приоритет |

# Какие логи собираем

Логирование должно быть структурированным (JSON) и унифицированным для всех сервисов.
Ключи — обязательные для корреляции:

* timestamp, trace_id, order_id, service, environment, level.

### INFO — обязательно

Логируем все бизнес-события, важные для заказов.

| Событие                         | Пример данных (JSON)                                                                                                                          |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Создание заказа (SUBMITTED)     | {"timestamp":"...", "level":"INFO", "event":"order_submitted", "order_id":"123", "user_id":"u456", "source":"B2C", "partner_id":null}       |
| Расчёт цены старт               | {"event":"pricing_started", "order_id":"123", "model_hash":"abc123", "polygon_count":12000}                                                 |
